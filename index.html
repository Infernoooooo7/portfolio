  1. 01

    Local-first AI

    In progress

    XODUS

    A local-first personal AI workspace and research testbed: local Ollama models only, a SQLite knowledge base with checked citations, and a built-in approval and audit layer.

    • Python
    • FastAPI
    • TypeScript
    • Next.js
    • SQLite
    • Ollama
    1. Static Next.js UIServed by the backend, with no Node process at runtime
    2. FastAPI + StepGateLoopback-only; one gate for schemas, permissions, paths and approvals
    3. Ollama + SQLiteLocal models only; FTS5 + sqlite-vec knowledge base
    • A local-first personal AI workspace and research testbed. A loopback-only FastAPI backend (127.0.0.1) serves a static Next.js UI and streams chat from a local Ollama model. It uses local models only and refuses cloud-hosted ones.
    • Its knowledge base is a single SQLite file (FTS5 keyword index plus sqlite-vec vectors) with hybrid retrieval, and answers carry checked [chunk:ID] citations.
    • Safety is built in: one enforcement point (StepGate) for schemas, permissions, paths and approvals; approvals bound to action hashes; a hash-chained audit log; a resource governor; and a process supervisor using Windows Job Objects.
    • It also doubles as a research testbed: a formal study (Gate G) comparing ReAct with plan-then-execute agent designs is in progress, per the README.

    Runs locally only, so there is no live demo. Description based on the repository README.

  2. 02

    Multi-agent AI

    Multi-Agent AI Resume Analyzer

    Three sequential CrewAI agents compare a resume with a job description, ending in an evidence-based verdict that can say “Insufficient Information”.

    1. Resume + job description
    2. Keyword match
    3. ATS score (est.)
    4. Eligibility verdict
    • Python
    • CrewAI
    • LLM APIs
    • A sequential three-agent CrewAI pipeline that compares a resume with a job description. The agents handle keyword matching, an estimated ATS-compatibility score, and an evidence-based eligibility assessment in turn.
    • The eligibility agent is limited to a fixed three-way verdict (Eligible, Not Eligible, Insufficient Information), so missing resume evidence produces an explicit “Insufficient Information” instead of an inferred judgment.

    Vision + LLM

    Reality Debugger

    Turns a camera feed, photo or video into a bug report for a physical scene, using on-device detection and an optional, rate-limited LLM layer.

    1. Camera · photo · video
    2. Detect + track
    3. FastAPI rule engine
    4. LLM (optional)
    • Python
    • FastAPI
    • Pydantic
    • React
    • ONNX Runtime
    • Built with Claude as an AI coding agent: a web app that turns a camera feed, photo or video into a bug report for a physical scene, using on-device detection (EfficientDet-Lite0, YOLOX-S) and ByteTrack tracking feeding a FastAPI rule engine.
    • Adds an optional LLM layer (Gemini, Claude or OpenAI-compatible) with Pydantic-validated JSON output. Calls are capped at 6 per minute with a cooldown, a 2-minute cache and error back-off, and local results stand if the LLM fails.

  5. 05

    Hackathon · Security

    PhishForensics

    Our BugBash 2026 hackathon entry. I wrote its FastAPI engine: it parses raw emails and scores each URL on 11 weighted signals, calling VirusTotal only when local risk is high.

    1. Raw email
    2. 11 URL signals
    3. VirusTotal (above threshold)
    4. PDF report
    • Python
    • FastAPI
    • SQLite
    • VirusTotal API
    • ReportLab
    • React
    • I wrote the FastAPI engine of our hackathon entry. It parses raw emails, flags sender / Return-Path mismatches, expands redirects, and scores each URL on 11 weighted signals such as homograph similarity, entropy and raw-IP hosts.
    • It queries the VirusTotal v3 API only for URLs above a local risk threshold, and caches verdicts in SQLite to limit calls to the rate-limited service. I also built the Chrome extension client and the ReportLab PDF reports.
    Source on GitHub (opens in a new tab) Live demo (opens in a new tab)
